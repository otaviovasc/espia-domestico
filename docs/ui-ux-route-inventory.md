## Current UX, styling, accessibility and responsive risks

These are source findings or risks requiring browser confirmation, not invented runtime failures.

1. **Theme coverage is absent at platform level.** App `index.css` forces `color-scheme: light`; primitives and pages hardcode white/zinc/violet. Masculine and bio HTML force dark; home uses a separate cream/brown serif direction. There is no unified light/dark/system preference lifecycle. Theme work must cover raw inputs/selects, popovers, all studio tabs, empty/error states, scrollbars and browser color-scheme, not only the shell. Intentionally dark video/canvas content needs explicit isolation.
2. **Generic app hierarchy competes with very complex work.** Shopping emoji brand, violet/pink gradient, white rounded cards and repeated equal-weight sections make unrelated operational and creative tasks feel alike. Many 10–12px utility labels and dense controls lower readability. The public home already uses cream/serif/terracotta styling; changing the app to that same generic pattern would not establish a product-specific studio identity. Final direction remains the design lead's responsibility.
3. **Authentication labels are not programmatically connected.** Shared `Label` accepts only children, so it cannot pass `htmlFor`; login fields have no IDs. Similar Label/Input sibling patterns occur in connection, safety and catalog editors. Upgrade primitive props and migrate consumers or use wrapping labels. Login error lacks `role="alert"`; generic Spinner has no accessible status text.
4. **Campaign error states are incomplete.** CampaignsPage never renders `query.isError` or retry. Detail treats `isLoading || !c || !safety` as spinner, so missing campaign/404/network error can leave an indefinite loader. Invalid route IDs become Number values without a distinct not-found view. These cases deserve explicit recoverable states.
5. **Connection loading/errors can look disconnected.** `statusQuery` error is not displayed and fallback badge reads disconnected. Disconnect mutation has no error output. Mode buttons do not expose selected state, and QR/phone radios lack a shared name/group legend. Pending, unavailable, and truly disconnected should be differentiated.
6. **OfferSender has incomplete modal semantics.** Fixed overlay has no dialog role/name/aria-modal, focus trap, Escape handler or focus restoration, and its icon-only close button lacks an accessible name. Use a shared accessible dialog pattern, keeping local selection/send behavior intact. Fullscreen preview already has a hook with Escape, focus trap/restore and scroll lock; avoid regressing it.
7. **Inbox errors/autoscroll/mobile need attention.** Messages query error is not rendered; `!loading && messages.length===0` can therefore show empty content after failure. The same issue can conflate group-load failure with empty list. Every data refresh triggers smooth `scrollIntoView`, which may steal the reader's position and ignores reduced motion in JS. Group list and thread stack on mobile inside a height-constrained app, while composer has three controls on one row; test 320px, keyboard viewport, long group names and media.
8. **Shared shell scroll/navigation needs integrated QA.** `h-full` flex shell, full mobile top navigation, fixed-width desktop sidebar and inner `main overflow-y-auto` interact with chat nested scrollers and sticky studio controls. Main lacks `min-w-0`, skip link and explicit navigation landmark name. Focus after SPA navigation is not managed. Confirm reachable controls at 200% zoom and very short screens.
9. **Wide data surfaces need responsive alternatives or deliberate scrolling.** Product review and per-file progress tables scroll horizontally; group history uses a minimum width and nested scrolling. Campaign list rows do not wrap their summary/status layout. Product editor, bulk assignment, pagination and generated output toolbars need narrow-width/long-text checks.
10. **Studio complexity is wider than the main editor.** Ads includes ~2,400-line page plus ~1,100-line StudioTools and 742-line carousel UI. Fixed minimum input widths, 2-column workspace minima, sticky render bar and tall preview `100dvh` calculations need testing at tablet/landscape/mobile keyboard sizes. Do not hide less-visible calendar/results/workbench capability while simplifying the primary editor.
11. **Keyboard and motion support has useful existing foundations.** Emoji picker, fullscreen hook, native details, clip reorder button alternatives/live announcements, preview controls and reduced-motion CSS are already present. Preserve them while bringing incomplete shell/forms/modal states to the same baseline. Generic button focus treatment should be consistent; do not rely on hover/title alone for meaning.
12. **Public-page source is independent and partly precompiled.** Home and masculine HTML contain large embedded Tailwind output plus custom styles/scripts. CSS global edits in the app cannot theme them. Existing carousels have keyboard/swipe/reduced-motion/visibility behavior and image fallback paths that must be retained. Home empty-carousel fallback currently exposes implementation-oriented copy about the `reviews` array; replace with useful end-user fallback during the authorized redesign. Preserve actual review assets/content and CTA destinations.

## Minimum verification coverage for the rebuild

- Build/typecheck and ESLint after integration; existing import/studio/creative/preview tests after changes touching relevant behavior. Existing tests cover data/config contracts, not visual completeness.
- Every route in the matrix: light, dark and system with persisted preference and OS change; signed-out redirect, loading, empty, failure and retry where meaningful; unknown app route and unknown/missing campaign.
- At least 320px/390px mobile, 768px tablet, 1280px desktop and short landscape viewport; 200% zoom; long real titles/group names and populated catalog/render data. Confirm no accidental horizontal page overflow or unreachable action.
- Keyboard-only navigation, visible focus, associated field labels, modal Escape/trap/restore, landmark/heading order and live errors/progress. Verify reduced motion for both CSS and scripted inbox/carousels.
- Authenticated browser validation must distinguish read-only navigation from business actions. Exercise sends, classification/AI calls, uploads, renders, destructive operations and publication edits only in the authorized test scope; fixtures or mocks must be labeled as such.
- Preview/render media parity checks stay separate from UI screenshot approval. Protect artwork colors, captions, timing/framing/audio/safe zones, generated download behavior and revision/autosave failures.
- Public production-style build serving: `/`, `/bio`, `/masculino`, `/painel` deep links, image fallbacks, CTA destinations and tracking retention. A development-server screenshot alone does not prove static-host release behavior.
