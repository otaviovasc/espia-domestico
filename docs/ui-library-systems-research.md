# Bibliotecas de componentes e sistemas de interação

Pesquisa em fontes primárias verificada em **15/10/2026**. Escopo: plataforma autenticada/login do Espia Doméstico; páginas públicas excluídas. Artefato de pesquisa, sem instalar dependências ou alterar a aplicação.

## Resultado e recomendação

Foram avaliados **18 sistemas distintos**: **8 bibliotecas com apresentação pronta**, **6 fundações de interação sem estilo** e **4 ferramentas específicas**. Os 17 pacotes publicados consultados declaram compatibilidade de peer com React 19; Park UI foi verificado como código sobre Ark UI/Panda CSS, sem fingir que existe um pacote `@park-ui/react`. Licenças: **16 MIT e 2 Apache-2.0**. O resultado de compatibilidade é documental, não execução de uma integração.

As três opções mais adequadas para uma prova pequena na plataforma são:

1. **HeroUI v3**, se a prioridade é aproveitar controles já polidos. A documentação atual exige precisamente **React 19+ e Tailwind 4**, e oferece ComboBox múltiplo, Drawer, Toast, Tabs, Tooltip e ProgressBar. Adaptar tokens, densidade e modo escuro ao brief; não importar a linguagem visual de demonstração inteira. A instalação requer estilos próprios e peers React Aria. [Quick start](https://heroui.com/en/docs/react/getting-started/quick-start), [ComboBox](https://heroui.com/en/docs/react/components/combo-box), [styling](https://heroui.com/en/docs/react/getting-started/styling).
2. **React Aria Components + os exemplos oficiais com Tailwind**, se a prioridade é controle visual e acessibilidade com componentes reutilizáveis. A documentação atual contém implementação copiável com estilo, `ComboBox` múltiplo, `Sheet`, `DropZone` e `ProgressBar`. Isso é mais pronto que iniciar os comportamentos do zero, mas ainda exige transformar os exemplos em componentes locais coerentes. [ComboBox](https://react-aria.adobe.com/ComboBox), [Select](https://react-aria.adobe.com/Select), [Sheet](https://react-aria.adobe.com/Sheet).
3. **Base UI**, se a prioridade é uma base independente com excelente cobertura de formulários. O ComboBox oficial inclui múltipla seleção, chips, pesquisa assíncrona e virtualização; estilos são livres e não vêm embutidos. É opção para substituir a camada de comportamento dos controles, sem trocar o Tailwind ou o roteamento. [ComboBox](https://base-ui.com/react/components/combobox), [styling](https://base-ui.com/react/handbook/styling).

São **alternativas de fundação**, não uma proposta de instalar as três. Como complemento isolado, **Sonner** é a opção mais direta para notificações; se HeroUI Toast ou a fundação escolhida já resolver a necessidade, manter apenas um sistema de notificações. **Ariakit** e **Headless UI** também merecem uma prova curta para seleção pesquisável quando o objetivo for alterar poucos controles.

O frontend existente declara React `^19.2.0`, Tailwind `^4.1.17`, Vite 7, React Router 7 e TanStack Query 5, sem framework de componentes instalado em `achadinhos-frontend/package.json`. Nenhuma recomendação requer migrar esse stack. A seleção final deve respeitar o contrato de tokens, tema e fluxos de `docs/ui-ux-design-brief.md`.

### O que esses custos significam aqui

- **HeroUI:** sete dependências diretas não representam custo total. React Aria, React Aria Components, utilitários e datas aparecem também como peers, além de `@heroui/styles`. Validar a resolução completa no lockfile da prova. O CSS precisa de escopo/cascata que preserve páginas públicas e a folha de tokens existente.
- **React Aria:** o pacote agrega Stately, Aria, datas e internacionalização; usar os subpaths documentados quando disponíveis, medir o chunk de verdade e não concluir que os 6.61 MiB descompactados serão enviados ao navegador.
- **Base UI / Ark / Headless / Ariakit / Radix:** sem um styling runtime obrigatório, mas com trabalho real de composição, CSS, ícones e tokens. O número de módulos internos de Ark não é evidência de que todos estarão no bundle final.
- **Mantine / Primer / Blueprint:** introduzem CSS e convenções de tema próprios. Não assumir que “aceita className” torna a adoção visual gratuita. Blueprint também distribui ícones e normalize como dependências; avaliar CSS global antes de qualquer import.
- **Chakra / MUI / Ant:** compatíveis com React 19 e capazes de coexistir com Tailwind; o motivo para não escolher agora é o custo de um segundo sistema visual e de estilos, não incompatibilidade de versão. Não confundir licenças MIT dos pacotes abertos com bibliotecas Pro/premium.
- **Sonner / cmdk / dropzone:** pequenos em escopo. `cmdk` e Vaul ainda trazem Radix; usar uma ferramenta focada não significa ausência de transitivas.

Nenhum tamanho de bundle foi medido nesta pesquisa. Uma prova deve comparar `vite build` antes/depois, tamanho gzip dos chunks efetivamente carregados e CSS novo, usando apenas um seletor e um overlay representativos. Não instalar várias fundações para fazer uma comparação visual; uma prova por vez é suficiente.

## Acessibilidade, foco, movimento e tema: aceite da prova

A biblioteca fornece mecanismos; a composição da aplicação ainda determina o resultado. Testar estes critérios no mesmo fluxo, em **390px e desktop**, nos dois temas:

1. **Seleção pesquisável:** campo com label visível, descrição de múltipla seleção, foco e seleção distinguíveis; toda operação possível por teclado. Testar busca vazia, erro remoto, lista longa, remoção de chip, retorno à pesquisa e manutenção de seleção ao mudar de página. Não trocar semântica de `listbox` por um menu de ações.
2. **Dialog/drawer:** heading anunciado, Tab/Shift+Tab contidos quando modal, Escape e botão de fechar, retorno a um acionador existente, fundo não operável e rolagem previsível. Conferir overlay dentro de outro overlay e abertura por diferentes botões. O Radix documenta explicitamente focus trap e retorno ao trigger; isso não dispensa a prova da composição final.
3. **Notificações:** sucesso por região live sem deslocar foco; erros importantes permanecem na página. Sonner possui `aria-live="polite"` e foco de região via Alt+T no código atual. Traduzir mensagens e rótulos; não anunciar dado factual inventado.
4. **Movimento reduzido:** preferência `prefers-reduced-motion: reduce` desliga translação, saltos e shimmer não essenciais; estados continuam claros sem animação. HeroUI documenta suporte à preferência nativa e `data-reduce-motion`; Sonner inclui CSS específico. Nos componentes sem estilo, a aplicação é responsável por qualquer animação adicionada. [HeroUI animation](https://heroui.com/en/docs/react/getting-started/animation), [Sonner CSS](https://github.com/emilkowalski/sonner/blob/main/src/styles.css).
5. **Tema e cascata:** continuar com `espia-theme` e `html[data-theme]` do brief. Mapear os tokens de componentes ao contrato sem criar segunda preferência independente; conferir popovers portados ao body, disabled, erro e foco. Não alterar cores de QR code, produtos, mídia ou exportação. Se CSS de uma biblioteca usar `.dark`, adaptar o seletor/escopo de forma deliberada; não presumir que ele já segue `data-theme`.
6. **Estados e limites:** loading, vazio e erro com retry separados; dados realmente disponíveis, sem coleções inteiras só para um seletor; aria/progresso ligados ao estado real; foco não perdido por polling e listas não remontadas desnecessariamente.

## Limites e descarte explícito

- **Vaul descartado para nova adoção:** aviso direto de ausência de manutenção. A presença em exemplos/registros de terceiros não revoga esse aviso.
- **Park UI sem instalação recomendada:** fontes oficiais confirmam Ark/Panda, mas as páginas de instalação tentadas retornaram 404/timeout e o suposto pacote React não existe no endpoint consultado. O resultado não prova que o projeto esteja inativo; somente impede prescrever uma instalação não verificada.
- **Chakra, MUI, Ant, Blueprint e Primer não são incompatíveis com o stack.** Foram colocados atrás das opções preferidas por peso de integração, identidade visual e sobreposição de estilos. Mantine permanece uma reserva válida se uma prova mostrar que seu formulário pronto compensa o novo CSS/tema.
- **Não adotar múltiplos sistemas de overlay/toast só para ampliar o catálogo.** Misturar foco, scroll locks e portais exige prova específica. `cmdk` fica condicionado a uma necessidade de comandos; upload HTTP e progresso real continuam na camada existente.
- **Nenhuma instalação, compilação de candidato, benchmark, teste com leitor de tela ou prova autenticada foi executado.** Fontes oficiais foram obtidas por HTTP; páginas client-only/URLs movidas foram verificadas por fonte do repositório quando possível. Context7 foi usado para localizar/examinar os exemplos atuais de React Aria e os pontos decisivos foram confirmados nas páginas oficiais.
- **Fontes voláteis:** README e docs podem mudar, e as versões `latest` também. Os links de metadados fixados acima registram as versões desta pesquisa. O passo seguinte é escolher uma fundação e provar **um seletor pesquisável + um overlay + um estado de erro** sob os critérios acima; não é uma migração de framework.
